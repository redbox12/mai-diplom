# Интеллектуальный тренажёр технических собеседований по DS



## 1. Цель

Веб-тренажёр для подготовки к техническим собеседованиям по Data Science. Вопросы берутся из записей реальных и мок-собеседований, эталонные ответы — из проверенных текстовых источников. Пользователь отвечает на вопрос, система показывает разбор ошибок и исправленный ответ.

Архитектурный акцент — конвейер обработки данных + RAG.

## 2. Целевая аудитория

- MVP: кандидаты уровня Junior.
- Развитие (вне MVP): Middle и Senior.

## 3. Источники данных

| Назначение | Источники |
|---|---|
| Вопросы («что спрашивают на рынке») | Видео реальных и мок-собеседований: YouTube, VK Видео, Rutube |
| Эталонные ответы («как правильно отвечать») | GitHub-репозитории со сборниками вопросов, статьи Хабра, официальная документация |

Принцип: из видео берётся только вопрос. Ответ кандидата из видео эталоном не считается, потому что в мок-собеседованиях кандидаты часто ошибаются. Эталон собирается из текстовых источников через RAG.

## 4. Функциональные требования

### 4.1. Пользователь

- Регистрация, вход, личный кабинет.
- Два уровня сложности:
  - **Лёгкий** — тест: выбрать верный вариант из нескольких.
  - **Сложный** — ответ своими словами.
- Ответ на сложном уровне получает:
  - разбор ошибок (что неверно, что упущено);
  - исправленный (эталонный) ответ;
  - вердикт: «верно» / «частично» / «неверно» — для статистики прогресса, без баллов.
- История прогресса: какие вопросы пройдены, вердикты, статистика по темам.
- Режим «самые частые вопросы» — вопросы ранжированы по частоте появления в собеседованиях.
- Карточки для запоминания:
  - пользователь сам добавляет вопрос в карточки (автоматического добавления нет);
  - система может предлагать добавить часто встречающиеся вопросы;
  - повторение карточек по интервальной схеме (как в Anki).

### 4.2. Администратор

- Запуск конвейера обработки на новых видео и текстах.
- Пополнение базы знаний в любой момент — это и есть «динамическое обновление базы знаний» (научная новизна).
- Ручная проверка эталонных ответов, помеченных как спорные.

Пользователь ничего в систему не загружает.

## 5. Конвейер обработки данных

1. Загрузка видео: yt-dlp + ffmpeg (извлечение аудио).
2. Транскрибация: через API.
3. Диаризация: разделение реплик интервьюера и кандидата.
4. Извлечение вопросов из транскриптов (LLM).
5. Нормализация и объединение похожих вопросов по эмбеддингам, подсчёт частоты.
6. Разметка вопросов по темам (ML, статистика, Python, SQL и т. д.).
7. Сбор эталонных ответов из текстовых источников (RAG).
8. Генерация тестов для лёгкого уровня: верный ответ + правдоподобные неверные варианты. Генерируются заранее и хранятся в базе.
9. Пометка спорных эталонов на ручную проверку.

## 6. Архитектура

| Компонент | Технологии | Ответственность |
|---|---|---|
| Frontend | веб-приложение (React или аналог) | Интерфейс тренажёра |
| Backend | **Go** | Авторизация, аккаунты, сессии, прогресс, карточки, API для фронтенда. Узкая область: CRUD + авторизация + вызов ML-сервиса по REST |
| ML-сервис | **Python** (FastAPI) | Конвейер обработки, RAG, генерация тестов, проверка свободных ответов |
| Реляционная БД | PostgreSQL | Пользователи, прогресс, карточки, вопросы, тесты |
| Векторная БД | Qdrant (клиенты для Go и Python) | Эмбеддинги вопросов и эталонных текстов |
| LLM | через API (DeepSeek и др.) | Извлечение вопросов, эталоны, тесты, проверка ответов |

Приложение запускается локально, нейросети вызываются через API.

## 7. Вне рамок MVP (развитие)

- Уровни Middle и Senior.
- Агентный режим: адаптивный выбор следующего вопроса по слабым темам, уточняющие вопросы как у живого интервьюера.
- Автоматическое обновление базы по расписанию.
- Локальные модели вместо API.

## 8. Открытые вопросы

| № | Вопрос | Статус |
|---|---|---|
| 1 | Объём базы для MVP (число видео / уникальных вопросов) | Не определён. Ориентир для обсуждения: 50–100 видео → 300–500 уникальных вопросов |
| 2 | Конкретный API для транскрибации и диаризации | Выбрать и сравнить по качеству на русском и цене |
| 3 | Конкретные каналы и репозитории-источники | Составить список 3–5 источников каждого типа |
| 4 | Метрики качества для текста ВКР | Предложены в разделе 9, утвердить с научным руководителем |

## 9. Предлагаемые метрики (для ВКР)

- Качество транскрипции: WER на выборке вручную размеченных фрагментов.
- Качество извлечения вопросов: точность и полнота на 10–20 вручную размеченных видео.
- Качество объединения дублей: доля верно объединённых пар.
- Качество разбора ответов: экспертная оценка или оценка другой LLM на контрольном наборе ответов.
